\section{Hiện thực hệ thống}

\subsection{Nền tảng sử dụng}

\subsubsection{Python 3.11 và gRPC}

\textbf{Python 3.11} là ngôn ngữ chính cho AI Pipeline. Lý do chọn Python:
hệ sinh thái ML/AI phong phú nhất (\texttt{sentence-transformers},
\texttt{pdfplumber}, \texttt{openai}); cộng đồng lớn; asyncio native hỗ trợ
I/O-bound workload hiệu quả.

\textbf{gRPC + Protobuf:} Giao thức giao tiếp giữa các service. Ưu điểm so
với REST/JSON: binary encoding nhanh hơn $\sim$3--5x, schema strongly typed
qua \texttt{.proto}, hỗ trợ streaming response.

\subsubsection{MinIO Object Storage}

MinIO là hệ thống object storage mã nguồn mở tương thích S3 API. Trong đề
tài, MinIO lưu trữ file tài liệu gốc (PDF, DOCX, PPTX). Bucket chính:
\texttt{documents}. Mỗi file có key: \texttt{\{owner\_id\}/\{doc\_id\}/original.\{ext\}}.

\subsubsection{Qdrant Vector Database}

Qdrant chạy trong Docker container, persistent volume tại
\texttt{./data/qdrant}. Collection \texttt{document\_chunks}: vector 768
chiều, metric cosine, payload gồm \texttt{document\_id}, \texttt{chunk\_id},
\texttt{heading}, \texttt{language}.

\subsubsection{Redis Cache và Job Queue}

Redis được sử dụng cho hai mục đích. Thứ nhất, Redis lưu semantic cache cho
Chatbot để giảm số lần gọi LLM với các câu hỏi tương tự. Thứ hai, Redis đóng
vai trò hàng đợi nhẹ cho AI Pipeline: API Service enqueue job sau khi upload
tài liệu, còn AI Pipeline worker consume job và cập nhật trạng thái xử lý sau
mỗi bước.

\subsubsection{React + TypeScript --- Frontend}

Frontend được xây dựng bằng \textbf{React 18 + TypeScript + Vite}. Thư viện
UI: \textbf{Tailwind CSS} + \textbf{shadcn/ui} (headless components). Giao
tiếp với Backend qua \textbf{gRPC-Web client} thông qua Envoy proxy.

\subsubsection{Docker và Docker Compose}

Hệ thống được đóng gói bằng Docker Compose với các service chính gồm API,
AI Pipeline worker, Frontend, Qdrant, MinIO, Postgres, Redis và Envoy proxy.
Cách tổ chức này giúp triển khai đồng nhất giữa môi trường phát triển và môi
trường demo, đồng thời đơn giản hóa việc cấu hình mạng nội bộ giữa các
service.

\subsection{Hiện thực AI Pipeline}

\subsubsection{Module Document Parsing}

Ba parser được triển khai thông qua cùng một interface trừu tượng để bảo đảm
tính nhất quán trong luồng xử lý đầu vào. Mỗi parser nhận file gốc và trả về
một cấu trúc tài liệu đã chuẩn hóa, bao gồm văn bản, heading và thông tin phân
đoạn. Với PDF, hệ thống sử dụng \texttt{pdfplumber} để trích xuất nội dung và
heuristic dựa trên font size hoặc định dạng chữ nhằm phát hiện heading.

\subsubsection{Module Text Chunking}

Sau khi parsing, tài liệu được chia thành các chunk theo cấu trúc heading.
Những section ngắn được giữ nguyên, còn section dài được cắt bằng cơ chế
sliding window có overlap để tránh mất ngữ cảnh ở ranh giới giữa các đoạn.
Cách làm này giúp cân bằng giữa độ đầy đủ ngữ nghĩa và giới hạn token đầu vào
của mô hình sinh nội dung.

\subsubsection{Module sinh nội dung AI}

Tầng sinh nội dung AI được hiện thực thông qua adapter kết nối tới LLM. Từ
mỗi chunk đầu vào, hệ thống sinh ra hai loại đầu ra chính: tập ý tóm tắt ngắn
gọn và bộ câu hỏi quiz trắc nghiệm. Các prompt được chuẩn hóa theo định dạng
JSON để giảm sai khác cấu trúc đầu ra và đơn giản hóa bước kiểm tra dữ liệu ở
backend.

\subsubsection{Use Case ProcessDocument}

Use case trung tâm của hệ thống điều phối toàn bộ pipeline xử lý tài liệu. Sau
khi người dùng tải file lên, API Service lưu file vào MinIO, tạo bản ghi với
trạng thái \texttt{QUEUED} và đẩy một job vào Redis queue. AI Pipeline worker
sau đó consume job, lần lượt thực hiện các bước parse, chunking, sinh
embedding, sinh nội dung AI và lưu kết quả vào cơ sở dữ liệu. Trạng thái xử
lý của tài liệu được cập nhật sau từng giai đoạn để frontend có thể hiển thị
tiến trình theo thời gian thực. Ở bước sinh nội dung, các chunk được xử lý
theo batch nhằm giảm nguy cơ vượt rate limit và tận dụng khả năng xử lý song
song.

\subsection{Tổng kết Chương 5}

Chương 5 đã trình bày chi tiết việc hiện thực hệ thống: lý giải lựa chọn
từng nền tảng công nghệ, mã nguồn cốt lõi của AI Pipeline (Parser, Chunker,
LLM Adapter, Use Case) và giao diện Web Application cho cả hai nhóm người dùng.
Toàn bộ mã nguồn được tổ chức theo kiến trúc DDD, đảm bảo tính modular và
dễ kiểm thử --- cơ sở để tiến hành kiểm thử toàn diện trong Chương 6.
